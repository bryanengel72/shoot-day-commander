# State Schema: Shoot Day Commander

Three files per shoot. No database, no connectors. Plain text the photographer
owns, opens in Excel or Numbers or Sheets, and edits by hand whenever they want.

```
shoots/
└── meridian-law-2026-09-14/
    ├── roster.csv      ← source of truth, one row per person
    ├── shoot-day.md    ← the shoot's header and close-out numbers
    └── run-sheet.md    ← generated day-of document, print or phone
```

One folder per shoot, named `client-slug-YYYY-MM-DD`. Keeping shoots separate
means one client company's employee list never sits in the same file as
another's.

## roster.csv

The only file that carries per-person state. `build_schedule.py` reads it, adds
`slot_time`, initializes `attendance`, and writes it back. Everything after that
is edited in place, by hand or by the skill.

| Column | Filled by | Values |
|---|---|---|
| `name` | Client roster | Real names only. Never invented, never padded. |
| `department` | Client roster | Drives `--by-department` grouping. Optional. |
| `email` | Client roster | Needed for prep mail and the selection chase. |
| `notes` | Client roster or photographer | Accommodations, extra time, arrives late. |
| `slot_time` | Script | `HH:MM`, 24 hour. Recalculated on every rebuild. |
| `attendance` | Day-of | `Scheduled`, `Photographed`, `No Show`, `Recaptured` |
| `selection_status` | Post-shoot | `Not Applicable`, `Gallery Sent`, `Not Opened`, `Opened No Pick`, `Selected` |
| `selected_image` | Post-shoot | Filename or gallery reference once picked. |

A minimal roster is one column, `name`. Everything else is optional and can be
filled in later.

`selection_status` stays `Not Applicable` under the on-site model, where the
pick happens during the session. Under gallery-after, the three middle values
are what the chase groups on, since someone who never opened the gallery needs
the link again rather than a reminder to decide.

**Status flow.** Attendance runs `Scheduled` → `Photographed` or `No Show`. A
`No Show` becomes `Recaptured` once photographed at a later session, which is
what keeps the recapture list honest instead of letting people quietly
disappear off it.

## shoot-day.md

The shoot's header, plus the close-out numbers. Generated by the script with
`[CONFIRM: ...]` placeholders for anything not passed in, then filled in by
hand or by the skill.

Carries: client, date, location, coordinator, status, selection model, the
schedule summary, and the close-out block. Status runs `Planning` →
`Scheduled` → `Comms Sent` → `Shot` → `Selections Open` (gallery-after only) →
`Delivered` → `Closed`.

The close-out block holds the one number that matters most: **per-person
minutes (actual)**, measured as shooting time divided by people photographed.
That number graduates to LEARNINGS.md at Workflow E.

## run-sheet.md

Generated output, disposable, regenerate freely. Timeline with breaks
interleaved, plus a check-in list. Prints to one or two pages. Any flags the
script raised appear near the top so they cannot be missed on the day.

## Reading state back in a fresh session

The skill spans weeks across separate sessions, so state has to survive the gap.

**Claude Code or Cowork:** the files sit on disk and persist on their own. Read
the shoot folder at the start of any workflow.

**claude.ai chat:** there is no writable disk between sessions. The photographer
downloads `roster.csv` and `shoot-day.md` at the end of a session and uploads
them at the start of the next. Say this plainly when handing files over, since a
photographer who does not re-upload arrives at Workflow D with nothing to work
from.

Always read `shoot-day.md` and `roster.csv` before continuing a shoot. Never
reconstruct a roster from memory or from earlier in the conversation.

## Optional: Notion or Sheets

Neither is required and neither is the default. The CSV is the source of truth
either way. If a photographer wants a live view the client coordinator can
watch, mirror `roster.csv` into a Google Sheet through Drive MCP, or into Notion
if they already run one. Mirror in one direction only, from the CSV outward.
Two sources of truth is how a roster ends up wrong.
